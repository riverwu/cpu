# CPU 产品设计

> v1.0 · 2026-10-29（P0–P2 完成）。本文定义 CPU 是什么、不是什么，以及每个交互决定背后的理由。§4–§9 描述目标形态；哪些已经实现、哪些还没做，见 §11。工程实现见 README。

## 1. 一句话

**把鼠标交给它，说出你要的结果。**

CPU 是住在你电脑里的一双手。你说一个目标，它就在你正在用的应用里、用你已经登录的账号把事情做完。整个过程你看得见、能打断，也随时可以自己接手。

## 2. 和 Codex 类工作 agent 的区别

两者的心智模型不同。

- **Codex 类 agent 像"派活给远程同事"**：开一个任务，它在独立的工作区里干几分钟到几小时，最后交回一个产物（PR、文档）等你审。
- **CPU 像"请坐在旁边的同事帮你弄一下"**：就在你眼前、在你的屏幕上做，几十秒到几分钟完成。结果就是你应用里的状态变了。

| | Codex 类工作 agent | CPU |
|---|---|---|
| 在哪儿干活 | 独立的工作区、沙盒、代码仓库 | 你的屏幕、你的应用、你的登录态 |
| 开始前要准备什么 | 选项目、配环境、授权连接器 | 不用准备：Fn Fn，开口说 |
| 上下文从哪来 | 你来提供：文件、仓库、链接 | 你正在看的东西就是上下文（"这个"） |
| 时长 | 分钟到小时，异步 | 秒到几分钟，同步、看得见 |
| 产出 | 一个产物，等你审 | 应用里的状态变化，加一句话报告 |
| 主界面 | 对话线程、任务列表 | 一张随叫随到的任务卡 |
| 你的角色 | 委托人、审阅人 | 旁观者，随时能接手 |
| 出错时 | 重跑，或修改说明 | 当场打断、纠正、接手 |

由此得出七条设计原则。后文每个设计决定都应该能追溯到其中一条：

1. **零准备**：从按键到开始说话不超过 0.3 秒。不需要先选模式、选项目或选工具。
2. **所见即上下文**：当前窗口、选中的文字、选中的文件就是"这个"，用户不必描述它们在哪儿。
3. **当着你的面做**：每一步都看得见（虚拟光标加一句人话），而不是在后台黑箱里跑。
4. **你永远优先**：按 Esc 立刻停；你一动鼠标或键盘，它就让开；任何时候都能接手。
5. **结果落在你的应用里**：不留下需要你再去搬运的中间产物；报告会告诉你结果在哪儿。
6. **只做短任务**：目标是 3 分钟内完成。超过这个时长的事说明不适合 CPU，应该拆分，或交给别的工具。
7. **走你会走的路**：用和你一样的通路做事：菜单、对话框、应用自带的功能（查找替换、修订、导出、浏览器自带翻译）和它们的快捷键，过程看得懂、合理，随时能接手。不为了快去走看不见的捷径。脚本、代码这类特别通路只在常规路径走不通或明显不合理时用（比如 300 个文件逐个改名），并在卡片上说明。速度来自熟练（知道熟练用户会怎么走），不来自绕开界面。

## 3. 什么是"任务"

任务是**一个有明确完成状态的目标**。它通常需要好几步，常常跨应用，完成后可以检查结果。

好任务一般有这些特征：
- **有终点**：比如"把……加到日历""把……整理成表""把……归档到……"。
- **依赖屏幕上下文**：比如"这封邮件""这些文件""这个表格"。
- **步骤繁琐但不需要判断力**，或者判断标准用户一句话就能说清。

示例：

| 场景 | 例子 |
|---|---|
| 邮件 → 日历 | "把这封邮件里的评审会加到日历，提前 15 分钟提醒" |
| 整理文件 | "把下载文件夹里的发票按月份放进 文稿/发票" |
| 表格 | "把这个表里状态是延期的项目挑出来，按负责人汇总到新的 sheet" |
| 跨应用汇总 | "把 POPO 项目群今天提到的待办整理到备忘录" |
| 填表 | "用这份简历的信息把这个网页表单填好，先别提交" |
| 查询比较 | "在 12306 查明天上午去上海、二等座还有票的车次" |
| 批量编辑 | "把这份 PPT 里所有标题字体改成苹方粗体" |
| 系统设置 | "打开夜览，并开启勿扰到下午 6 点" |

### 3.1 价值大的场景
共同点：有界面没接口、跨应用、步骤琐碎、结果可以检查。按从真实使用中看到的价值排序：

| 场景 | 例子 | 为什么适合 |
|---|---|---|
| 读懂眼前的东西 | 这张表怎么选、这篇公众号讲了什么、对照财报原文看文章说得对不对 | 内容就在你的应用里，CPU 能读全文、翻页、打开原文，省掉复制粘贴；只读，风险低 |
| 跨应用搬运 | 邮件里的会议加日历、表格几行发给同事、发票信息填进报销系统 | 应用之间没有接口，人只能切窗口复制粘贴 |
| 文档编辑 | 润色、翻译、校对 | 必须在原应用里改、保留格式，按审阅的习惯来（见 3.2） |
| 格式转换和导出 | 网页、表格、文档存 PDF | 打印面板、保存面板最烦人；结果一查就知道 |
| 批量重复 | 每行做一遍、整理下载文件夹 | 配合示范学习和快捷说法 |
| 内部系统 | 审批、报销、工单 | 没有开放接口，又天天要用 |

### 3.2 场景的预期约定（场景剧本）
同一个动词，用户期待的做法不同；模型默认倾向"直接做掉"。真实例子：说"优化一下这篇文章"，模型把全文选中重打成一个副本，而用户期待的是先看改了哪里。

通用约定：
1. **先分清是"看"、"建议"还是"改"**：检查、分析是只读；优化、润色先给建议；"直接改"才直接改。
2. **原件不丢**：Word 里开修订，或另存副本，改动可以撤回。
3. **改动看得见**：展示原文 → 新文和理由，而不是只说"改好了"。
4. **就地小改**：逐处替换，保留格式；不全选重打。
5. **结果找得到**：说清楚在哪，给打开的按钮。

每类场景有一段"剧本"：用户的预期，加熟练用户的做法。请求里的词选中剧本，和请求一起交给模型，每个任务只给一次。内置剧本：改写润色、校对、翻译、读懂分析、导出 PDF、填表。用户可以在 `~/.config/cpu/playbooks/<id>.md` 写自己的版本覆盖内置的。

支撑剧本的两个能力：
- **读全文**：像读屏软件一样读整页或整篇文档，包括屏幕之外的部分（2026-10-29 决定：读可以超出屏幕，动作必须看得见）。不暴露正文的应用（Word、Pages）通过应用自己的脚本接口只读地取正文，取不到时读它保存的文件并注明"未保存的修改不在其中"。**从不经过剪贴板**（2026-10-30 决定）。
- **改动预览卡**：模型把修改建议交给卡片，逐条显示"原文（划掉）→ 新文 + 理由"，可以勾选，"应用 N 处"或说"好"；只应用勾选的。

不适合的任务，以及该怎么处理：
- **单句通讯**（"跟王宁说一句话"）：说什么本质上是用户自己的表达，让模型代写反而危险。CPU 能做，但会先拟一句草稿请你确认（见 §6）。这条规则来自一次真实事故：模型自己编了一句"在忙吗？最近怎么样"，准备直接发给联系人。
- **开放问答**（"量子计算是什么"）：没有任何操作，应该交给聊天助手。
- **长期项目**（"帮我做完这个功能"）：应该交给 Codex 类工具。
- **定时或持续监控**（"每天 9 点……"）：v1 不做，见 §10。

## 4. 任务的一生

```
Fn Fn 唤起 ─▶ 说出目标 ─▶ 开始执行 ─▶ [需要你：确认 / 交还] ─▶ 完成报告 ─▶ 跟进，或 Fn Fn 关闭
   │            │            │                 │                      │
 上下文胶囊    停顿后自动提交   卡片实时叙述步骤      卡片变成问题，等你回答     卡片保留，等你关闭
```

### 4.1 唤起
- **Fn Fn**：在任何应用里双击 Fn，卡片出现在当前屏幕上方居中，并立刻开始听。卡片不抢焦点，你原来的应用仍然是前台应用，所以它就是默认的上下文。
- **上下文胶囊**：卡片顶部显示 CPU 现在看到的东西，比如"📎 邮件 ·「下周评审会议安排」"、"📎 选中的 3 段文字"、"📎 访达 · 选中的 12 个文件"。点 ✕ 可以移除。胶囊回答了两个问题："这个"指的是什么，以及哪些信息会发给模型。
- **后台预热**：唤起的同时，后台已经开始读取当前窗口、预热网络连接，目标是说完话后 2 秒内执行第一个动作。

### 4.2 表达
- **说话**：
  - 免提：停顿约 1 秒后自动提交。
  - 按住 Fn 说话，松开即提交。
- **打字**：一开始打字就切换到键盘输入，回车提交。
- 一句话应该就够了，不要求固定格式。"这个""这几个""刚才那个"这类指代，由上下文胶囊来确定指的是什么。

### 4.3 开始：理解确认要轻
- **默认直接开始**，不弹"计划确认"。卡片标题会立刻变成模型改写后的**目标句**，比如"把评审会加到日历（10/30 14:00）"。这一句就是理解确认：看一眼不对，直接说"不对，是……"或者按 Esc。
- **只有两种情况先问再做**：
  - 目标有关键歧义，比如"哪个王宁？"
  - 第一步就是不可逆的动作。

  问题以选项的形式给出，可以直接说"第一个"。

### 4.4 执行：看得见、能打断、可接手
- **让开工作区**：任务一开始，卡片缩成屏幕右上角（菜单栏下方）的一个小胶囊，只显示目标、刚做完的一步和停止按钮，屏幕中间留给正在被操作的内容。点胶囊展开完整卡片，点 ⌃ 收回胶囊。
- **人话步骤**：展开后的卡片显示"打开 日历""新建事件：评审会议""设置时间 10/30 14:00"这样的步骤，而不是 `[12] button`。显示最近 6 步；完成后整个过程折叠成"做了 N 步操作"一行，点开可看。
- **虚拟光标**：屏幕上的虚拟光标指向正在操作的位置。
- **后台优先**：能通过辅助功能接口完成的动作不碰你的鼠标，你可以同时做别的事。
- **共享这台电脑**：CPU 和你同时用一台 Mac，互不干扰。详见 §4.8。
- **随时纠偏**：执行中按住 Fn 说"改成下周三"，这句话会加入当前任务，不用停下来重来。
- **停止与收起**：
  - Esc：立即停止，包括正在等待的模型请求。
  - Fn Fn：只收起卡片，任务继续。菜单栏图标变为"进行中"，完成后结果卡片自动回来。

### 4.5 需要你：确认与交还
有两种"需要你"的情况。卡片都会变成一个问题，发出一声轻提示音，并开始听你的回答。
- **确认**：即将执行对外或不可逆的动作。卡片会展示**预览**，比如收件人和正文、要删除的文件列表、要提交的表单摘要。可以点按钮（确认 / 修改 / 取消），也可以直接说"发吧""改成……"。
- **交还**：遇到只能由你来做的步骤，比如登录、验证码、扫码、支付密码、系统授权弹窗。卡片会写明"请你完成登录，完成后 Fn Fn 继续"。CPU 在这期间等待，你回来后它从当前界面接着做。

交还是正式的流程，不算失败。它把"我做不到"变成"这一步你来，剩下的我做"。

### 4.6 完成：结果、证据、去哪儿看
- **卡片保留，不自动隐藏**，直到你按 Fn Fn、Esc 或点 ✕ 关闭。
- **报告结构**：一句话结果，加上证据，再加一个"打开"按钮。比如："已在日历创建「评审会议」10/30 14:00–15:00，邀请 3 人 ·〔打开日历〕"。"打开"会把对应的窗口带到前台。
- **失败也给出路**：说明卡在哪儿，并提供〔重试〕〔我来接手〕〔换个说法〕，绝不只丢下一条错误信息。

### 4.7 跟进与关闭
- **卡片开着，就还是同一件事。** 这时再说话就是跟进，沿用刚才的上下文，比如"再发给李四""把时间改到 3 点"。
- **Fn Fn 关闭卡片，这件事就结束了。** 下次 Fn Fn 是一个新任务。
- 这条规则让用户不需要理解"会话"的概念：看得见卡片，就还在说这件事。
- **卡片显示整个会话。** 从唤起到关闭的每一轮都留在卡片上：你说的话在右侧气泡里，每轮的步骤折叠成"做了 N 步操作 · 用时"一行，下面是这一轮的回答。完成后滚到最新一轮的开头；执行中跟着最新的步骤。
- **历史记录**：每轮结束都会保存这个会话（`~/Library/Application Support/CPU/sessions/`，保留最近 300 个）。点卡片右上角的时钟或菜单栏的"历史记录…"打开历史窗口：左边按天列出会话，可以搜索；右边是完整内容，可以"再做一次"。

### 4.8 共享这台电脑
目标：CPU 执行时**不碰你的鼠标指针、不抢前台、不打断你打字**；你的鼠标和键盘也不影响它。做法是把每类动作都改成"先在后台做"，只有后台确实做不了时才短暂借用前台。

| 动作 | 后台做法（不动指针、不抢前台） | 后台做不了时 |
|---|---|---|
| 按按钮、选列表、勾选、展开 | 辅助功能语义操作 | — |
| 在界面元素上输入 | 辅助功能直接写入 | 逐字按键事件发给目标进程 |
| ⌘ 快捷键 | 在目标应用的菜单里找到对应菜单项，直接按下 | 借用前台 |
| 按坐标点击（微信这类自绘界面） | 鼠标事件只发给目标进程、指定目标窗口；即使窗口被挡住也能点 | 截图前后对比没有变化 → 借用前台 |
| 读界面 | 辅助功能大纲；窗口被挡住也能截到它自己的画面 | — |
| 打开应用或网址 | 在后台打开，不抢前台 | 用户要看时（`show`）才带到前台 |
| 拖拽 | — | 借用前台 |

借用前台的规矩：
- 先等你停手（0.6 秒没有输入，最多等 3 秒）。
- 动作本身约 0.2 秒；被挪开的鼠标指针立即复位。
- 这一批动作做完，前台还给你原来的应用。
- 需要临时切换输入法时，也先等你停手。

已用探针实测，探针窗口处在后台并且被遮挡，前台是终端：
- 后台坐标点击原生按钮 ✅
- 后台菜单快捷键 ✅
- 后台写入原生输入框 ✅
- 后台向网页输入框逐字输入 ✅
- 借用前台后把前台还回去 ✅
- 用真实模型跑完整个计算器任务，前台始终没变 ✅

两个已知限制：
- **网页按钮**在不活跃窗口里会忽略坐标点击。这是 WebKit 的行为，只能借用前台。不过网页元素大多有辅助功能信息，可以用语义操作代替坐标点击。
- 后台点击用到了 macOS 的未公开接口：事件字段 51 和 `CGEventSetWindowLocation`。在运行时检测，不存在时自动退回到借用前台。

剩下的冲突是**逻辑上**的：如果你和 CPU 同时在改同一个应用的同一处内容，后到的那一方会覆盖先到的。CPU 每批动作后都会重新观察界面，发现异常会调整，或者问你。

## 5. 界面形态

界面就是一张卡片，有两个位置、两种形态：

| 时机 | 位置 | 形态 |
|---|---|---|
| 唤起、说出或输入请求 | 屏幕中上方（像 Spotlight，这时你正看着它） | 卡片，宽 640pt |
| 执行中 | 右上角，菜单栏下方 | 胶囊，宽 340pt：目标 · 刚做完的一步 · 停止 |
| 提问、确认、交还、完成 | 右上角 | 卡片，宽 520pt（一行约 33 个汉字）；整个会话按轮显示，回答是 Markdown 渲染，过长时在卡片内滚动，底边渐隐提示还有内容 |

- 你把右上角的胶囊或卡片拖到别处，以后的任务就停在那里。
- 窗口大小始终等于卡片本身（外加阴影边距），卡片之外不挡任何点击。
- CPU 自己要用真实鼠标点击时，卡片在那一瞬间让点击穿过。

不同状态下的内容如下（示意，宽度按上表）：

```
空闲 / 聆听                          执行中
╭──────────────────────────────╮   ╭──────────────────────────────╮
│ 🎙 正在听…                 ✕ │   │ ◐ 把评审会加到日历            │
│ 📎 邮件 ·「下周评审会议安排」  │   │   ✓ 读取邮件中的时间和参会人   │
╰──────────────────────────────╯   │   ✓ 打开 日历                 │
                                   │   ▸ 新建事件「评审会议」…      │
                                   │ Esc 停止 · Fn Fn 收起         │
                                   ╰──────────────────────────────╯
确认                                完成
╭──────────────────────────────╮   ╭──────────────────────────────╮
│ ? 发送这封邮件？               │   │ ✓ 把评审会加到日历          ✕ │
│   收件人：张三、李四           │   │ 已创建 10/30 14:00–15:00，    │
│   「评审改到周四下午…」        │   │ 邀请 3 人，提前 15 分钟提醒。  │
│ [确认] [修改] [取消]  🎙 说也行 │   │ [打开日历]  12 步 · 18 秒     │
╰──────────────────────────────╯   │ 🎙 按住 Fn 继续说…            │
                                   ╰──────────────────────────────╯
```

视觉原则：
- 一张卡片，只有一个焦点。
- 技术细节（步数、耗时、token）放在最下面一行小字。
- 颜色只用来区分状态：进行中、需要你、完成、失败。

## 6. 信任与安全

**确认分级**决定 CPU 什么时候打断你：

| 级别 | 例子 | 行为 |
|---|---|---|
| 只读 | 查看、搜索、读取、截图 | 直接做 |
| 可撤销的编辑 | 改文档或表格、存草稿、把文件移到新文件夹 | 直接做，报告里列出改动 |
| 对外或不可逆 | 发送、提交、发布、删除、付款、改系统设置 | 先确认，并展示预览 |
| 敏感 | 密码、验证码、支付密码、系统授权 | 不代做，交还给你 |

原则是**在可能的范围内尽可能自动化**：如果你的话已经包含了这个动作需要的全部信息，对外动作也直接做。比如"把这份周报发给张三"，收件人和内容都明确了。但**只要内容是模型自己写的，就一律先确认**。

其他保障：
- **看得见**：虚拟光标、人话步骤、上下文胶囊。
- **停得下**：Esc 在全局都有效，并且会立即取消正在进行的模型请求。
- **不越界**：
  - 屏蔽密码管理器、钥匙串等应用。
  - 屏幕内容只发给你配置的模型。
  - 运行记录只存在本机，保留 7 天。
- **能复原**：为了点击而挪开的窗口，任务结束后会放回原处。

## 7. 接入工作流

- **在哪儿都能唤起**：Fn Fn 不需要先切到 CPU。选中即用：先选中文字或文件，再 Fn Fn，"这个"就是你选中的东西。
- **拖进来**：把文件拖到卡片上，作为上下文。
- **结果留在原处**：结果就在日历里、表格里、文件夹里，报告提供"打开"按钮。
- **做过的事可以再做**：菜单栏里有"最近任务"，一键"再做一次"。常用的可以起个名字作为快捷说法，比如说"日报"就执行一段完整的指令。
- **和你并行**：CPU 在后台执行，你在它工作时照常用电脑（§4.8）。

## 8. 速度与准确：产品指标

| 指标 | 目标 |
|---|---|
| 按键 → 开始听 | < 0.3 秒 |
| 说完 → 第一个动作 | 中位数 < 2 秒 |
| 每步模型耗时 | 中位数 < 1.5 秒 |
| 典型任务（5–15 个动作） | < 30 秒 |
| 任务完成率（不需要你接手） | > 80% |
| 误操作率（点错，或做了没要求的事） | < 1% |
| 接手率（你中途接手或纠偏） | 持续追踪，越低越好 |

速度来自已经实现的工程手段：AX 优先、批量动作、动作后自动观察、界面稳定检测、提示词缓存、OCR 预热等。准确来自：索引加文字双重核对、OCR 子串定位、遮挡自动处理。

## 9. 快捷键

| 操作 | 效果 |
|---|---|
| Fn Fn（卡片关着时） | 唤起并开始听 |
| Fn Fn（卡片开着时） | 关闭卡片；如果任务在进行，就只收起卡片，任务继续 |
| 按住 Fn（卡片开着时） | 按住说话：说新任务、跟进、回答问题，以及执行中插话（插话是 P0） |
| Esc | 执行中：停止；聆听中：取消；其他情况：关闭 |
| 回车 | 提交打字内容 |

冲突提示：macOS 的"按下 🌐 键时"设置，以及听写快捷键"按两下 🌐"，都会和 Fn Fn 冲突。首次启动时要检测并引导用户到 系统设置 → 键盘 修改（P0）。不想改系统设置的用户，可以在配置里换成组合键，比如 `ctrl+alt+space`。

## 10. v1 不做什么

- 不做定时、后台监控和自动触发。
- 不做跨设备和远程控制。
- 不替你输入密码、验证码或支付信息。

**编程环境**（2026-10-30）：模型原本借界面里的编程环境写代码（在脚本编辑器里写 AppleScript、在浏览器控制台里写 JavaScript），拿不到返回值。现在有 `code` 工具：

**读取文字**（2026-10-30 晚）：一次真实任务（"这篇文章说了啥？"，87 秒）里，`read` 只给了网页前 6 万字且没有办法往下读，模型就用 `cpu page` 在隐藏浏览器里重新加载同一网页三次（71 秒），拿到的也未必是用户看到的版本。按语义拆分并统一长文本：
1. `read_window`：窗口显示的全部文字，任何应用都适用，页面没加载完会等；文字同时存进工作目录供 `read_file` 和代码使用。`read_file`：文件的文字（纯文本和代码、rtf/doc/docx/odt/html、PDF 按页），也是读长结果后续部分的方式。网页 = `open` + `read_window`。
2. 长文本统一规则：读窗口、读文件、代码输出、超过 2000 字的选中文字，结果最多显示一段，全文存成文件，结果写明"显示第几行到第几行，共多少行；从第几行接着读，或用代码搜索"。
3. 不完整要说出来：读到时间或数量上限、编辑器只加载了屏幕上那部分（滚动条显示只占一部分）、窗口文字明显少于它对应的文件，都会注明。
4. 剪贴板是用户的：CPU 自己读和输入都不再碰剪贴板（Word 改用它的脚本接口；后台输入不再借粘贴，改为发按键，文字里的换行用 Shift+Return，不会在聊天应用里提前发出）。模型要拷贝或剪切（⌘C、⌘X、拷贝/复制/剪切菜单或按钮）、代码要写剪贴板（pbcopy 等）时先请用户确认。
5. 存有密码和密钥的位置（~/.ssh、~/.aws、钥匙串、.env 等）`read_file` 不读。
6. `cpu page` 的说明写明它是在隐藏浏览器里重新加载、不带登录、要 5–20 秒，只用于没打开的网页或存成图片/PDF。
实测：17.4 万字的文本编辑文档 0.1 秒读完；问第 1500 行的内容，模型读窗口后用代码 `sed` 在存下的全文里取出，3 步 4.5 秒；全程剪贴板计数不变。

**语音断句**：豆包 0.8 秒静音标记一句结束；话尾看起来没说完（"……的""然后""那个"、逗号结尾）时继续等，安静约 1.8 秒才提交；说完整的句子仍在约 0.8 秒后提交。
